# 그룹 관리 PRD

## 1. 문제와 목표

### 문제

- 사용자는 반복해서 함께 정산하는 사람을 매번 공개 ID나 연락처로 다시 찾아야 한다.
- 현재 서버에는 정산 개발용 그룹 명단 Stub만 있고, 실제 그룹 생성·가입·구성원 관리 기능은 없다.
- 그룹에서 선택한 정산 참여자가 어느 그룹에서 왔는지 저장하지 않아 실제 그룹 상태와 정산을 연결할 수 없다.
- 그룹을 나가거나 멤버를 제거할 때 진행 중 정산 의무를 우회하지 못하게 하는 공통 정책이 없다.

### 목표

- 사용자가 자주 정산하는 사람을 그룹으로 만들고 초대 코드 또는 OWNER 직접 추가로 구성원을 관리할 수 있다.
- 활성 그룹 구성원을 정산 참여자 후보로 재사용할 수 있다.
- OWNER 이전, 자기 탈퇴, 멤버 제거가 단일 역할·정산 의무 규칙을 지킨다.
- 그룹을 삭제해도 이미 시작한 정산 기록은 보존한다.

### 성공 기준

- 그룹 생성자는 생성 직후 유일한 `OWNER`가 되고 초대 코드와 공유 링크를 받을 수 있다.
- 활성 멤버는 자신의 그룹 목록·상세·멤버 목록을 조회할 수 있다.
- 사용자는 초대 코드로 가입하고, OWNER는 공개 ID로 멤버를 직접 추가하거나 제거된 멤버를 복구할 수 있다.
- 그룹 기반 정산 후보에는 실제 `ACTIVE` 멤버만 나타난다.
- 진행 중 정산 의무가 있는 멤버는 자기 탈퇴와 OWNER 제거 모두 거절된다.
- 그룹 삭제 후 신규 접근과 가입은 차단되지만 기존 정산은 유지된다.

## 2. 사용자와 역할

| 역할 | 설명 | 주요 권한 |
| --- | --- | --- |
| `OWNER` | 그룹을 생성하거나 소유권을 넘겨받은 활성 멤버 | 그룹 설정 수정·삭제, 멤버 직접 추가·제거, 소유권 이전, 일반 멤버 기능 |
| `MEMBER` | 초대 코드 또는 OWNER 직접 추가로 참여한 활성 멤버 | 그룹 목록·상세·멤버 목록 조회, 초대 정보 복사, 자기 탈퇴, 그룹 기반 정산 후보 사용 |

- 한 활성 그룹에는 `OWNER`가 정확히 한 명만 존재한다.
- 별도 `ADMIN` 역할은 두지 않는다.
- 삭제된 그룹의 기존 멤버십은 감사와 정산 기록을 위해 보존하지만 어떤 역할 권한도 행사할 수 없다.

## 3. 범위

### 포함

- `GRO-001`: 그룹 생성
- `GRO-002`, `GRO-002-001`, `GRO-002-002`: 내 그룹 목록과 상세 조회
- `GRO-003`: 그룹 이름·메모·프로필 이미지 수정, 초대 정보 복사, 멤버 관리
- `GRO-004`: 기존 정산을 보존하는 그룹 소프트 삭제
- `GRO-005`: 고정 초대 코드와 공유 링크 제공
- `GRO-006`: 초대 코드 기반 그룹 가입
- `GRO-007`: 그룹 탈퇴
- OWNER 직접 추가·제거와 제거된 멤버 복구
- OWNER 소유권 이전
- 실제 그룹 구성원 기반 정산 참여자 후보·추가
- 진행 중 정산과 멤버 종료 정책 연동

### 제외

- `ADMIN` 등 추가 역할
- 초대 코드 만료, 회전, 재발급
- 서버의 SMS·메신저 초대 발송과 그룹 알림
- 가입 승인제와 초대 요청 대기열
- 그룹 목록·멤버 목록 페이지네이션
- 삭제 그룹 복구와 물리 삭제
- 그룹별 정산 내역 목록·통계 화면
- 클라이언트 기본 그룹 이미지 파일 제공

## 4. 핵심 사용자 흐름

### 4.1 그룹 생성과 공유

1. 로그인 사용자가 그룹 이름, 선택 메모, 선택 이미지를 입력한다.
2. 서버가 그룹과 생성자의 `OWNER` 멤버십을 하나의 작업으로 생성한다.
3. 서버가 그룹 수명주기 동안 고정되는 초대 코드와 공유 링크를 반환한다.
4. 클라이언트가 OS 공유 기능 등으로 링크를 전달한다.

### 4.2 내 그룹 조회와 설정 변경

1. 로그인 사용자가 자신이 `ACTIVE` 멤버인 그룹 전체를 최근 가입 순으로 조회한다.
2. 그룹을 선택하면 상세 정보, 활성 인원수, 초대 정보와 자신의 역할을 확인한다.
3. OWNER는 이름·메모·이미지를 변경하거나 기본 이미지 상태로 되돌릴 수 있다.
4. MEMBER는 설정을 변경할 수 없다.

### 4.3 초대 코드 가입과 재가입

1. 사용자가 공유 링크를 열거나 초대 코드를 입력한다.
2. 서버는 영문 대소문자를 구분하지 않고 활성 그룹을 찾는다.
3. 가입 이력이 없으면 `MEMBER`로 추가한다.
4. 자발적으로 나간 `LEFT` 멤버는 같은 멤버십을 `ACTIVE`로 되돌리고 가입 시각을 갱신한다.
5. OWNER가 제거한 `REMOVED` 멤버는 초대 코드로 재가입할 수 없다.

### 4.4 OWNER 직접 추가와 멤버 제거

1. OWNER가 정확한 사용자 공개 ID를 입력한다.
2. 가입 이력이 없으면 새 `MEMBER`로 추가한다.
3. `REMOVED` 상태면 OWNER 의사에 따라 복구한다.
4. `LEFT` 상태면 사용자의 자발적 이탈을 존중해 강제로 복구하지 않고 초대 코드 재가입을 안내한다.
5. OWNER가 멤버를 제거할 때 진행 중 그룹 출처 정산이 있으면 거절한다.

### 4.5 소유권 이전과 탈퇴

1. OWNER가 다른 활성 MEMBER를 새 OWNER로 지정한다.
2. 서버가 기존 OWNER를 MEMBER로, 대상을 OWNER로 한 작업 안에서 변경한다.
3. 일반 MEMBER는 진행 중 정산 의무가 없으면 자발적으로 탈퇴한다.
4. OWNER는 소유권을 먼저 이전한 뒤 탈퇴할 수 있다.

### 4.6 그룹 기반 정산 참여자 선택

1. 정산 생성자가 자신이 속한 그룹을 선택한다.
2. 서버가 그룹의 실제 `ACTIVE` 멤버 중 이미 정산에 포함된 사용자를 제외해 반환한다.
3. 생성자가 멤버를 고르면 참여자에 그룹 출처와 그룹 ID를 함께 저장한다.
4. 이후 멤버 탈퇴·제거 시 이 출처를 사용해 진행 중 정산 의무를 판별한다.

### 4.7 그룹 삭제

1. OWNER가 그룹 삭제를 요청한다.
2. 서버가 그룹을 `DELETED`로 전환한다.
3. 삭제 그룹은 목록·상세·가입·설정·멤버 관리에서 보이지 않는다.
4. 기존 멤버십과 정산 참여자·Share·송금 기록은 보존한다.

## 5. 제품 규칙

### 그룹 정보

| 항목 | 규칙 |
| --- | --- |
| 그룹 이름 | 필수, 앞뒤 공백 제거 후 1~20자 |
| 그룹 메모 | 선택, 앞뒤 공백 제거 후 최대 60자, 빈 값은 없음으로 처리 |
| 그룹 이미지 | 선택, JPEG·PNG·WebP, 최대 5 MiB |
| 기본 이미지 | 서버는 기본 파일을 저장하지 않고 이미지 없음으로 응답하며 클라이언트가 표시 |
| 목록 | 페이지네이션 없이 전체 반환, 현재 멤버십 `joinedAt` 내림차순 |
| 삭제 | 복구 없는 소프트 삭제 |

### 초대

| 항목 | 규칙 |
| --- | --- |
| 초대 코드 | 대문자 영숫자 8자리, 전체 그룹에서 고유 |
| 입력 | 대소문자를 구분하지 않으며 앞뒤 공백 제거 |
| 수명 | 그룹 생성부터 삭제까지 고정, 만료·회전 없음 |
| 노출 | 활성 멤버의 생성 결과·상세 조회에만 노출 |
| 공유 | 서버는 코드와 링크만 반환하고 실제 공유는 클라이언트가 수행 |

### 멤버십

| 현재 상태 | 초대 코드 가입 | OWNER 직접 추가 | 결과 |
| --- | --- | --- | --- |
| 이력 없음 | 허용 | 허용 | `ACTIVE MEMBER` 생성 |
| `ACTIVE` | 거절 | 거절 | 기존 멤버십 유지 |
| `LEFT` | 허용 | 거절 | `ACTIVE MEMBER`, `joinedAt` 갱신 |
| `REMOVED` | 거절 | 허용 | `ACTIVE MEMBER`, `joinedAt` 갱신 |

### 멤버 종료와 정산

| 관련 그룹 출처 정산 상태 | 자기 탈퇴 | OWNER 제거 |
| --- | --- | --- |
| 없음 | 허용 | 허용 |
| `DRAFT` | 허용 | 허용 |
| `REQUESTED` | 차단 | 차단 |
| `AWAITING_DEPOSIT` | 차단 | 차단 |
| `SUSPENDED` | 차단 | 차단 |
| `COMPLETED` | 허용 | 허용 |

- `SUSPENDED`는 재개 가능한 미완료 정산이므로 정산 의무가 해소될 때까지 차단한다.
- 자기 탈퇴와 OWNER 제거는 같은 종료 정책을 사용한다.
- 종료 후에도 기존 정산 참여자는 삭제하거나 다른 사람으로 바꾸지 않는다.

## 6. 상태와 의존성

### 그룹 상태

```text
ACTIVE -> DELETED
```

- `DELETED`에서 되돌아오는 상태 전이는 없다.

### 멤버 상태

```text
ACTIVE MEMBER -> LEFT    -> ACTIVE MEMBER  (초대 코드 재가입)
ACTIVE MEMBER -> REMOVED -> ACTIVE MEMBER  (OWNER 직접 복구)
ACTIVE OWNER  -> MEMBER  (소유권 이전)
ACTIVE MEMBER -> OWNER   (소유권 이전)
```

- OWNER는 `LEFT` 또는 `REMOVED`로 직접 전이할 수 없다.
- 소유권 이전 후 기존 OWNER가 MEMBER가 되어야 탈퇴할 수 있다.

### 다른 기능과의 의존성

- 인증: 모든 그룹 API는 로그인 사용자를 기준으로 한다.
- 사용자: OWNER 직접 추가와 멤버 응답은 사용자 `publicId`, 이름, 이미지 존재 여부를 사용한다.
- 정산: 기존 그룹 구성원 조회 Stub을 실제 활성 멤버 조회로 교체한다.
- 저장소: 그룹·멤버 스키마와 정산 참여자의 그룹 출처 컬럼이 선행되어야 한다.

## 7. 수용 기준

1. 그룹 생성 요청 하나로 그룹과 OWNER 멤버십이 함께 생성된다.
2. 이름·메모·이미지 규칙을 벗어난 요청은 저장 전에 거절된다.
3. 내 그룹 목록에는 활성 멤버십과 활성 그룹만 최근 가입 순으로 표시된다.
4. 비멤버는 그룹 상세·이미지·멤버 목록·초대 정보에 접근할 수 없다.
5. MEMBER는 그룹 설정 수정·삭제·직접 추가·제거·소유권 이전을 할 수 없다.
6. 초대 코드 가입의 신규·`LEFT`·`REMOVED`·`ACTIVE` 결과가 제품 규칙 표와 일치한다.
7. OWNER 직접 추가의 신규·`LEFT`·`REMOVED`·`ACTIVE` 결과가 제품 규칙 표와 일치한다.
8. 소유권 이전 중에도 활성 OWNER는 정확히 한 명이다.
9. OWNER는 소유권 이전 전 탈퇴할 수 없다.
10. 진행 중 정산이 있는 멤버는 자기 탈퇴와 OWNER 제거가 동일하게 거절된다.
11. 정산 후보는 실제 활성 그룹멤버만 사용하고 그룹 출처 ID를 저장한다.
12. 삭제 그룹은 신규 동작에서 숨겨지며 기존 정산은 그대로 조회·진행할 수 있다.
