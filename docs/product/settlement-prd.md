# PRD: 일회성 정산

- 상태: Draft
- 마지막 업데이트: 2026-08-21
- 관련 이슈: [#28](https://github.com/Team-HowMuch/howmuch-backend-v2/issues/28), [#27](https://github.com/Team-HowMuch/howmuch-backend-v2/issues/27), [#29](https://github.com/Team-HowMuch/howmuch-backend-v2/issues/29), [#26](https://github.com/Team-HowMuch/howmuch-backend-v2/issues/26)

## 1. 문제와 목표

### 문제

식사나 모임 뒤 비용을 나눌 때 생성자는 참여자, 각자의 부담 금액, 수령 계좌, 입금 현황을 여러 채널에서 따로 관리해야 한다. 단순 송금 요청만으로는 각 참여자가 무엇을 얼마나 부담하는지와 실제 입금 완료 여부를 일관되게 알기 어렵다.

### 목표

한 번의 정산에서 참여자 선정부터 배분, 공통 링크 공유, 송금 유도, 실제 입금 확인까지의 흐름을 제공한다. 생성자는 정산 상태를 확인하고, 참여자는 자신의 부담금만 빠르게 확인·송금한다.

### 성공 기준

- 생성자는 참여자·지출·정산 방식·수령 계좌를 지정해 정산 요청을 만들 수 있다.
- 더치페이는 참여자별 확정 금액을, 품목별은 각 참여자의 선택 결과를 근거로 개인 부담금을 제공한다.
- 하나의 공통 링크로 회원과 비회원 모두 정산에 참여할 수 있다.
- 실제 입금 여부는 CODEF 거래내역 검증 결과를 기준으로 완료 처리한다.

## 2. 사용자와 역할

| 역할 | 목표 |
| --- | --- |
| 정산 생성자 | 비용, 참여자, 배분 방식, 수령 계좌를 설정하고 입금 현황을 확인한다. |
| 회원 참여자 | 설치·검증된 앱 링크에서 로그인한 계정으로 본인을 식별하고 바로 자신의 정산 단계로 이동한다. |
| 비회원 또는 앱 미사용 참여자 | 브라우저에서 이름을 선택해 자신의 정산 단계로 이동한다. |
| CODEF 입금 현황 기능 | 수령 계좌 거래내역을 조회·매칭해 실제 입금 완료 여부를 판정한다. |

## 3. 범위

### 포함

- 정산 초안 생성·수정과 참여자 선택
- 수동 지출, 기존 결제내역, OCR 결과 기반 지출 등록
- 더치페이와 품목별 할당
- 수령 계좌 선택, 참여자별 Share 생성, 공통 참여 링크 생성
- OS 딥링크를 통한 앱·브라우저 진입과 클라이언트 native share sheet 공유
- Toss 송금 화면으로의 이동과 CODEF 입금 현황 기능으로의 완료 연계

### 제외

- 그룹 생성·수정과 결제수단 등록 자체
- OCR 이미지 인식 엔진과 CODEF 거래내역 매칭 구현 자체
- Toss가 실제 송금을 실행하도록 서버가 결제 API를 호출하는 기능
- 서버의 SMS·푸시 발송 및 클라이언트 native share sheet 구현
- CODEF의 모호한 거래 수동 확인, 자동 재조회 주기, 입금 현황 화면의 상세 정책

## 4. 핵심 사용자 흐름

### 4.1 생성자

1. 로그인한 생성자가 정산 초안을 만든다.
2. 사용자 ID 검색, 연락처 검색, 그룹 구성원 조회 결과에서 참여자를 선택한다.
3. 수동 입력, 기존 결제내역, OCR 결과 중 하나 이상으로 지출을 등록한다.
4. 더치페이 또는 품목별 할당 방식을 선택하고 수령 계좌를 고른다.
5. 정산 요청을 확정한다. 참여자, 지출, 정산 방식, 수령 계좌는 이후 수정할 수 없다.
6. 서버가 하나의 공통 참여 링크를 반환하고, 클라이언트는 휴대폰 기본 공유 기능으로 원하는 앱에 이 링크를 공유한다.

### 4.2 링크 진입과 참여자 식별

1. 참여자가 동일한 HTTPS 공통 링크를 누른다.
2. Universal Link 또는 Android App Link가 설치·검증된 앱을 열 수 있으면 앱이 링크 토큰을 받는다. 그 외에는 브라우저가 링크를 연다.
3. 앱에서 로그인 세션이 유효하고 현재 사용자와 정산 참여자가 연결돼 있으면 이름 선택 없이 해당 참여자의 단계로 이동한다.
4. 앱이 열렸지만 로그인 세션이 없거나 참여자와 연결되지 않았으면 브라우저 참여 흐름으로 전환한다.
5. 브라우저 참여자는 표시된 참여자 이름에서 본인을 선택한다. 이는 인증 없는 신뢰 기반 MVP이며, 오선택·입금자 불일치는 CODEF 입금 현황 기능에서 예외로 처리한다.

### 4.3 더치페이

1. 총액을 참여자 수로 균등 분할한다.
2. 원 단위로 나누어떨어지지 않는 잔액은 생성자가 부담한다.
3. 요청 확정 시 참여자별 Share를 확정한다.
4. 앱 또는 브라우저는 수령 계좌와 확정 금액으로 Toss 송금 화면을 연다.

### 4.4 품목별 할당

1. 생성자는 OCR 결과의 품목을 정산에 반영하고 참여 링크를 공유한다.
2. 참여자는 자신이 부담할 품목을 선택한다. 하나의 품목은 여러 참여자가 선택할 수 있으며 선택 비율은 `1`, `1/2`, `1/3`, `1/4`만 지원한다.
3. 모든 참여자의 선택이 끝나면 시스템이 각 참여자의 개인 부담금을 계산한다.
4. 모든 품목의 배분 합계가 지출 총액과 일치하면 Share를 확정하고 각 참여자는 Toss 송금 단계로 이동한다.
5. 모든 선택이 끝났는데 배분 합계가 맞지 않으면 정산은 중단 상태가 된다. 생성자는 내용을 수정한 뒤 새 요청을 만들어 다시 공유한다.

### 4.5 송금과 입금 완료

1. Toss 송금은 클라이언트가 유도하며 서버는 송금 실행 성공을 완료 근거로 사용하지 않는다.
2. 수령 계좌의 실제 입금 여부는 별도 CODEF 입금 현황 기능이 거래내역을 조회·매칭해 판정한다.
3. 모든 Share의 입금이 완료로 확인되면 정산도 완료된다.

## 5. 제품 규칙

| 영역 | 규칙 |
| --- | --- |
| 공통 링크 | 정산마다 하나의 링크만 만들며, 참여자별 별도 링크나 서버 메시지 발송은 제공하지 않는다. |
| 링크 라우팅 | 회원 여부가 아니라 앱 설치·검증과 로그인 세션을 기준으로 앱 또는 브라우저 흐름을 선택한다. |
| 앱 회원 | 로그인한 앱 회원은 현재 사용자와 연결된 참여자를 서버가 식별해 이름 선택을 건너뛴다. |
| 브라우저 참여 | 비회원·앱 미설치·로그아웃 사용자는 이름을 직접 선택한다. |
| 더치페이 | 생성 시 확정된 균등 분할 금액을 송금한다. 잔액은 생성자 몫이다. |
| 품목별 | 선택 비율만으로 배분하며, 모든 선택이 끝난 뒤 합계가 일치해야 송금 요청을 확정한다. |
| 요청 확정 | 확정된 참여자, 지출, 수령 계좌와 최종 Share는 변경하지 않는다. 수정하려면 새 정산 요청을 만든다. |
| 입금 완료 | Toss 화면 복귀나 사용자 선언이 아니라 CODEF가 확인한 수령 계좌 거래내역만 완료 근거로 사용한다. |

## 6. 상태와 의존성

| 상태 | 의미 | 다음 상태 |
| --- | --- | --- |
| 초안 | 생성자가 참여자·지출·방식을 수정하는 상태 | 요청됨 |
| 요청됨 | 공통 링크가 공유됐고 참여자가 더치페이 송금 또는 품목 선택을 진행하는 상태 | 입금 확인 대기, 중단 |
| 입금 확인 대기 | 최종 Share가 확정됐고 CODEF 입금 확인을 기다리는 상태 | 완료 |
| 중단 | 품목별 선택 완료 후 배분 합계가 일치하지 않는 상태 | 새 정산 요청 |
| 완료 | 모든 Share의 실제 입금이 CODEF에서 확인된 상태 | 종료 |

CODEF 입금 현황은 `PENDING`, `NEEDS_CONFIRMATION`, `COMPLETED` 같은 입금 단위 상태를 별도로 소유한다. 정산 기능은 확정된 Share와 수령 계좌 정보를 제공하고, CODEF 기능의 완료 결과만 받는다.

## 7. 수용 기준

- 회원이 설치·검증된 앱에서 공통 링크를 열면 로그인한 참여자를 자동 식별하고 바로 자신의 단계로 이동한다.
- 비회원 또는 앱을 쓸 수 없는 참여자는 동일 링크를 브라우저에서 열어 이름을 선택할 수 있다.
- 더치페이 Share의 합계는 총액과 같고, 나머지 원 단위 금액은 생성자에게 귀속된다.
- 품목별 Share는 허용된 비율만 사용하며, 합계가 맞지 않으면 송금 단계로 진행하지 않는다.
- 요청 확정 후 생성자는 기존 요청의 참여자·지출·수령 계좌·최종 Share를 바꿀 수 없다.
- 실제 입금이 CODEF에서 모두 확인되기 전에는 정산을 완료로 표시하지 않는다.
