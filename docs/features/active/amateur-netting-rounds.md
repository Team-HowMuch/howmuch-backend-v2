# 아마추어 압축 정산 회차 준비

- 상태: 구현 중
- 기준일: 2026-10-21 KST
- Flyway migration required: **No**. 기존 테이블에 격리된 시연 데이터만 추가한다.

## 목적과 범위

압축 실행 후 같은 네 폰에서 다시 15회 → 3회를 보여준다. 전체 템플릿을 재실행하면 사용자 ID와 연결이 바뀌므로, 승인된 운영 웹 화면에서 새 모임과 미납 5건만 준비한다. 사용자·인증 세션·계좌·CODEF·리캡·정기 설정·기존 압축 이력은 변경하지 않는다. 전체 초기화와 폰 화면 강제 이동은 범위 밖이다.

## 2026-10-21 운영 웹 연결 설계

- 기존 앱 컨테이너를 교체하거나 재시작하지 않는다. dev 호스트의 loopback 전용 Python 보조 서비스와 운영자 컴퓨터의 loopback SSH 연결로 제공한다. 외부 공개 포트를 열지 않는다. 다른 노트북 접속 요청에 따라 별도 Docker 서비스와 Cloudflare Quick Tunnel의 HTTPS 주소 배포를 준비했다. 임시 주소는 터널 재시작 시 달라지며 고정 도메인 연결은 별도 설정이 필요하다.
- 기존 앱의 ADMIN 전용 공통 코드 조회 API로 모든 업무 요청의 Bearer 권한을 확인한다. 관리자 로그인도 기존 앱을 사용하되, DB에서 활성 ADMIN임을 먼저 확인한다. 시연 계정·일반 계정 로그인은 전달하지 않아 폰 세션을 회전시키지 않는다.
- 데이터 보존을 위해 신규 Flyway 테이블은 만들지 않는다. 운영자 수동 폰 상태·작업 요청·회차 이력은 권한 0600의 전용 파일에 저장한다. DB 정산 데이터는 기존 트랜잭션 생성 도구를 재사용한다.
- 최초 검증된 기준 5건은 서버 전용 파일에 동결한다. 나중에 원본 모임이 변경되어도 이 기준으로만 복제한다. 계좌 암호문은 새 UUID에 맞춰 재암호화하고 토큰을 재발급한다.
- `NEXT`는 지정 회차의 성공한 실제 압축 후에만 허용한다. `RECOVER`는 기준 5건·분담금·입금·그룹 내 추가 미납/압축 이력이 달라졌을 때만 허용한다. 진행 중인 압축은 두 동작 모두 차단한다.
- 예상 그룹 ID와 요청 UUID를 사용한다. 요청 UUID와 payload가 다르면 409, 같은 요청 재전달은 같은 결과를 반환한다. DB commit 후 파일 쓰기 실패도 결정적 모임 ID로 복구하며 새 모임을 중복 생성하지 않는다.
- 폰 상태는 운영자가 공유 상태로 표시한다. revision 충돌을 감지한다. 하나라도 금액 설명 중이면 서버도 회차 생성을 차단한다. 앱 자체의 조작을 막는 기능은 아니다.
- 실제 데이터 조회 시각·회차 상태·작업 결과를 표시한다. 서버 단절 시 마지막 조회 값을 구분하고 준비를 비활성화한다. 준비 요청의 결과 불명은 재생성 대신 요청 결과 조회를 먼저 수행한다.
- `GET /console/api/state`, `PUT /console/api/phones`, `POST /console/api/rounds`, `GET /console/api/requests/{uuid}`. 로그인/갱신만 명시된 원본 auth API로 전달하며 임의 upstream proxy는 제공하지 않는다.
- 프런트는 승인된 피그마 기반 초안의 HTML/CSS를 실제 운영 화면으로 옮긴다. 상황 미리보기·가상 상태 코드는 제거한다. 기존 관리자 콘솔은 변경하지 않는다.

## 검증·배포 단위

부스 사진에 맞춰 PPT·영상 모니터와 네 폰 운영을 구분한다. 왼쪽 한승환·최영헌 자유 체험, 오른쪽 문채원·최수아 설명 시연용 기본 템플릿을 제공한다. 설명자는 단계 안내/다음 단계/시연 시작·마치기를 사용하며 실제 앱 화면을 자동 이동시키지 않는다. 시작·마침은 오른쪽 두 폰의 공유 수동 상태만 갱신한다.

그룹만 생성하는 템플릿도 제공한다. 리캡은 실행 중인 앱 이미지의 `BuildMonthlyRecapService`와 실제 persistence adapter/policy를 별도 JVM에서 호출한다. 두 번째 Spring Application이나 scheduler는 시작하지 않는다. 지난달까지 없던 확정 snapshot만 `insertIfAbsent`로 생성하고 이미 있는 8·9월 snapshot은 유지한다. 이번 달은 DB 저장 없는 미리보기만 지원한다. 제휴 혜택은 원래 서버와 동일하게 null이다.

기존 관리자 세션이 없어 별도의 dev 시연 운영자 ADMIN 한 계정을 추가했다. 기존 사용자들의 역할·PIN·세션은 수정하지 않는다. 새 운영자 PIN은 채팅/로그에 출력하지 않고 Git 제외된 `operator.credentials.private.json`(0600)에 전달한다.

추가 요청: 현재 네 계정에 한정한 정산 요청·독촉·리마인드·완료·입금 확인·리캡 알림 버튼을 제공한다. 실제 접근 가능한 정산/완료 이력/리캡이 있는 경우만 알림함과 기존 delivery outbox를 동일 트랜잭션으로 추가한다. 같은 요청 재전달은 중복 발송하지 않는다. 제공자 접수와 운영자가 확인한 폰 수신을 구분한다.

기본 더치페이·영수증 품목 선택·압축 5건 및 사용자 작성 템플릿을 별도 모임으로 생성한다. 제목·금액·생성자·참여자를 지정하고 템플릿을 파일로 최대 20개 저장한다. 영수증은 인식된 품목 정보가 준비된 상태부터 시작한다. 금액 설명 중에는 데이터 생성을 차단한다. 신규 스키마는 필요하지 않다.

1. 운영 서비스/상태 판정/멱등 생성, 구문 검사와 dev DB transaction rollback 검증.
2. 실제 화면/기존 ADMIN 인증/일반 계정 거부/공유 상태·작업 조회 검증.
3. 전용 user service 및 loopback SSH 연결 배포. 현재 계정·인증 세션·계좌·기존 정산·리캡·고정 지출 fingerprint 전후 비교.

기존 압축 전 5건을 검증 목적으로 압축하거나 변경하지 않는다. 전체 성공 경로는 독립 DB 트랜잭션에서 rollback 검증하고, 현재 회차의 실제 압축은 사용자가 폰에서 시연할 때 수행한다. 2026-10-21 사용자가 PR 생성을 요청했다. 배포/통합 검증 대기 항목을 남긴 초안 PR로 제출한다.

## 설계

- 입력은 현재 템플릿 manifest와 직전 압축 모임이다. 현재 네 사용자의 ID·번호·활성 상태를 검증한다.
- 기본 실행은 새 데이터의 INSERT를 한 트랜잭션에서 검증한 뒤 ROLLBACK한다. `--apply`만 저장한다.
- 저장은 직전 모임의 지정 5건이 실제 압축에 포함되고 CREATE 실행이 SUCCEEDED인 경우만 허용한다. 미압축 상태에서 실행하면 기존 모임을 반환한다.
- 회차의 초대 코드와 정산 UUID를 원본 실행·직전 모임에서 결정하여 중복 실행과 프로세스 중단 후 재시도를 처리한다. 템플릿과 같은 DB advisory lock을 사용한다.
- 원본 5건의 금액·참여자·카테고리와 동일한 새 정산을 만든다. 수신 계좌 암호문은 새로운 정산 UUID의 AAD로 다시 암호화하고 링크 토큰도 새로 발급한다.
- 신청 시각은 현재 UTC로 갱신하여 지난 회차의 은행 거래를 재사용하지 않는다. 입금·출금·은행 거래와 알림을 생성하지 않는다.
- 새 모임 ID와 회차 번호를 운영자 전용 JSON에 저장한다. 기존 모임과 진행 중인 다른 체험을 수정하거나 숨기지 않는다.

## 외부 접속 배포 설계

`deploy-console`은 지정한 콘솔 코드만 별도 디렉터리에 올리고 전 파일 `fsync`와 이미지 빌드가 성공한 뒤 전용 서비스만 교체한다. 앱/DB/CODEF 컨테이너와 기존 시연 manifest·계정·state는 교체하지 않는다. 컨테이너는 비root 사용자, cap-drop ALL, 읽기 전용 rootfs, loopback 서버를 사용한다. 기존 엔진이 실제 앱 JVM/DB에 접근하기 위해 Docker socket을 사용하므로 dev 운영자 전용 도구다.

Quick Tunnel 프로세스와 콘솔을 한 전용 컨테이너에서 감독하고 재시작 정책을 적용해 운영자 Mac의 SSH 세션과 분리한다. 서비스는 정확한 현재 HTTPS Host/Origin과 loopback Host만 허용한다. 모든 업무 요청은 기존 앱의 ADMIN 검증을 통과해야 한다. 로그인은 전체 1분 6회로 제한한다. 터널 프로세스가 끝나면 해당 임시 HTTPS 주소는 종료되며, 새 주소는 `console-state/public-origin.txt`에서 확인한다. 외부 접속 배포는 저장소 복구 후 실행한다.

## 운영상 한계

회차를 추가하면 같은 계정의 홈·AI 전체 금액에도 반영된다. 그룹만 격리하며 계정 전체 숫자를 고정하지 않는다. 실제 은행 입금을 병행하려면 수신 계좌 분리 등 별도 운영 규칙이 필요하다. 전체 템플릿을 재실행한 경우 새로운 manifest를 사용해야 한다.

## PR 범위와 커밋 단위

- `feat(demo): 부스 시연 운영 콘솔과 회차 준비 도구 추가` 기능 커밋으로 실제 UI·API·복제 엔진·배포 도구·운영 문서를 묶고, CLI 실행 권한은 별도 보완 커밋에 담는다. 별도 애플리케이션 변경이나 Flyway migration은 없다.
