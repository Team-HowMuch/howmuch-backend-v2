# 테스트 메서드명·설명 주석 컨벤션 정리

- Status: In progress
- Last updated: 2026-09-24
- Related issue: #411
- Related ADR: N/A

## 1. 목적

### 문제

`src/test/java`의 테스트 이름과 설명 주석 작성 방식이 일관되지 않아 테스트 목록만 보고 검증 대상, 핵심 조건, 기대 결과를 파악하기 어려운 경우가 있다. 일부 메서드명은 길거나 결과를 말하지 않고, 설정·Annotation 테스트와 일반 동작 테스트의 이름 구조도 구분되지 않는다.

### 지금 정리하는 이유

테스트가 늘어난 상태에서 기존 이름을 방치하면 실패 보고서와 코드 리뷰에서 테스트 의도를 찾는 비용이 커진다. 테스트 이름과 설명 주석 기준을 문서화해 후속 테스트에도 일관되게 적용한다.

### 성공 기준

- [ ] 최신 `develop`의 Java JUnit 테스트 메서드를 `<대상>_<핵심 조건>_<기대 결과>`로 정리한다.
- [ ] 설정·Annotation 테스트에는 `<대상>_<검증 속성>_<기대 상태>`를 적용한다.
- [ ] 필요한 Javadoc과 테스트 설명 주석은 완전한 동사형 문장(`~한다.`)으로 작성한다.
- [ ] 코드로 명확한 내용을 반복하는 주석을 추가하지 않으며, `@DisplayName`은 실제 검증과 다를 때만 수정한다.
- [ ] 테스트 메서드 수, Annotation, 본문, assertion, JavaScript 테스트를 보존한다.
- [ ] 규칙을 `docs/testing.md`에 기록한다.

### 범위 제외

- 테스트 동작, 본문, assertion, fixture 및 실행 순서를 변경하지 않는다.
- 테스트를 분리하거나 새 테스트를 추가하지 않는다.
- JavaScript 테스트 이름과 코드는 변경하지 않는다.
- 테스트 메서드 외의 production 코드 및 테스트 helper 메서드는 변경하지 않는다.

## 2. 현황과 용어

### 적용 경계

- 기존 도메인: 테스트 소스 전체에 걸친 표현 규칙이며 도메인 로직 변경은 없다.
- 적용 파일: 최신 `develop`의 `src/test/java/**/*.java`.
- 현재 파일 수: Java 테스트 파일 173개.
- 기준선 탐색: JUnit 테스트 Annotation 969개와 대응하는 테스트 메서드 969개를 확인했다.

### 용어

| 용어 | 의미 | 표현 |
|---|---|---|
| 대상 | 테스트가 검증하는 메서드, 상태, 계약 또는 설정 값 | 이름 첫 부분 |
| 핵심 조건 | 기대 동작을 바꾸는 입력이나 상태 | 이름 두 번째 부분 |
| 기대 결과 | assertion이 보장하는 결과 | 이름 마지막 부분 |
| 테스트 설명 주석 | 테스트 의도·회귀 이유를 코드보다 더 설명하는 주석 | 완전한 동사형 문장 |

## 3. 시나리오와 계약

### 정상 흐름

1. 최신 `develop`을 기준으로 Java 테스트 이름과 주석을 전수 검토한다.
2. 검증 대상과 조건, assertion 결과를 확인해 새 이름을 정한다.
3. 메서드 이름과 그 메서드의 필요한 설명만 한 변경 단위로 적용한다.
4. 변경 파일과 메서드 범위를 확인하고 `compileTestJava`를 실행한다.
5. 컴파일이 성공하면 해당 메서드만 커밋한다.
6. 문서 규칙과 최종 보존 여부를 확인한 뒤 전체 테스트와 CI를 확인한다.

### 실패 흐름

- 컴파일이 실패하면 해당 변경을 커밋하지 않고 이름/참조 범위를 수정한다.
- 메서드 이름만으로 기대 결과가 구분되지 않으면 메서드 본문과 `@DisplayName`을 확인하고, 필요할 때에만 이름 또는 표시 이름을 다듬는다.
- 통합 테스트 실행에 필요한 격리 PostgreSQL 또는 Redis가 준비되지 않으면 이를 성공으로 간주하지 않고 실행 불가 사유를 기록한다.

### 경계 조건

- 설정·Annotation 테스트에는 속성과 기대 상태가 식별되는 형식을 사용한다.
- 매개변수화된 테스트는 매개변수 하나로 바뀌는 조건을 식별한다.
- 테스트 메서드 이름은 의미 전달에 필요한 길이로 유지한다. 고정 글자 수 제한은 두지 않고, 중복 대상·세부 구현·불필요한 단어를 제거한다.
- 테스트 본문, assertion 및 모든 JUnit/기타 Annotation은 보존한다.

## 4. 설계 결정

### 명명과 주석

- 일반 테스트 이름 형식: `<대상>_<핵심 조건>_<기대 결과>`.
- 설정·Annotation 테스트 이름 형식: `<대상>_<검증 속성>_<기대 상태>`.
- Javadoc 및 테스트 설명 주석은 추가 의미가 있을 때만 작성하고 완전한 동사형 문장으로 끝낸다.
- 짧은 코드 보조 설명과 구역 표시는 명사형을 허용한다.
- 이름·코드가 이미 말해 주는 사실을 반복하는 주석은 추가하지 않는다.
- 기존 `@DisplayName`은 실제 테스트 동작과 불일치할 때만 수정한다.

### 트레이드오프

- 언어와 길이는 기존 영문 Java 식별자 관례를 유지하면서 세 의미 단위를 명확히 구분한다.
- 긴 이름을 기계적으로 자르지 않고, 실제 assertion 결과를 보존하는 짧은 단어를 사용한다.
- 테스트가 한 번에 하나의 동작만 검증하도록 분리하는 작업은 이 변경에서 수행하지 않는다.

## 5. 영향 범위

| 영역 | 영향 | 확인 대상 |
|---|---|---|
| Java 테스트 | 테스트 메서드명 및 해당 메서드 설명만 변경 | `src/test/java/**/*.java` |
| 문서 | 명명 및 주석 규칙 추가 | `docs/testing.md` |
| JavaScript | 변경하지 않음 | `src/test/js/**/*.cjs` |
| production 코드 | 변경하지 않음 | `src/main/**` |
| 실행 환경 | PostgreSQL/Redis가 필요한 전체 테스트 | `compose.test.yml`, `scripts/test.sh` |

기존 동작 중 유지할 사항:

- 각 테스트 메서드의 annotation, body, assertion, 실행 데이터와 검증 의미.
- `@DisplayName`의 기존 문구(테스트 내용과 어긋나지 않는 경우).
- 기존 테스트 개수와 JavaScript 테스트 전체.

## 6. 구현 단계와 커밋 경계

- [x] Migration-only PR: N/A. 데이터 구조 및 애플리케이션 계약을 바꾸지 않는다.
- [x] UseCase, Command/Result, Ports, Domain, Application, Adapter, API, Infra: N/A. 테스트 명명만 변경한다.
- [ ] 이 Feature Plan을 별도 문서 커밋으로 추가한다.
- [ ] Java 테스트 메서드명을 하나씩 변경한다. 메서드 이름과 그 메서드의 필요한 Javadoc, 테스트 설명 주석, 내용이 잘못된 `@DisplayName` 수정은 같은 커밋에 포함한다. 두 테스트 메서드의 변경을 한 커밋에 묶지 않는다.
- [ ] `docs/testing.md`의 규칙 변경은 별도 문서 커밋으로 둔다.
- [ ] 전체 변경 후 보존 검증을 기록하고 Feature Plan을 `docs/features/completed/`로 이동한다.

예상 커밋 제목:

```text
docs(tests): 테스트 메서드 명명 작업 계획 기록
test(tests): <한 메서드의 대상과 기대 동작을 나타내는 설명>
docs(testing): 테스트 메서드명과 주석 규칙 문서화
docs(tests): 테스트 명명 작업 완료 기록
```

각 Java 메서드 커밋 전 변경 범위에 그 메서드만 포함되는지 확인하고 `./gradlew compileTestJava`를 실행한다. 작성자와 커미터는 로컬 사용자 Git 설정을 사용하며 Co-authored-by 문구는 추가하지 않는다.

## 7. 검증

### 사전 기준선

- `./gradlew compileTestJava`: 통과.
- 전체 테스트 기준선: PostgreSQL/Redis 격리 서비스가 필요하다. 작업 환경에서 Docker 데몬이 실행되지 않았고 `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `REDIS_HOST`, `REDIS_PORT`가 설정되지 않아 `bash scripts/test.sh`는 실행할 수 없었다.

### 명령

```bash
./gradlew compileTestJava
bash scripts/test.sh
git diff --check
git status --short --untracked-files=all
gh pr checks <PR_NUMBER>
```

### 완료 기준

- [ ] 메서드 수와 JUnit Annotation 수가 기준선과 같다.
- [ ] 테스트 메서드 선언을 제외한 본문과 assertion이 변경되지 않았다.
- [ ] JavaScript 테스트가 변경되지 않았다.
- [ ] 전체 격리 테스트 실행 결과와 PR CI 결과를 기록한다.
- [ ] 문서 링크와 Git 작성자/커미터 및 Co-authored-by 부재를 확인한다.
