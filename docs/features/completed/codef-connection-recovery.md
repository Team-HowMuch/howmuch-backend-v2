# 기능 계획: CODEF 연결 상태 복구와 조회 자격정보 재사용

- 상태: 로컬 구현 완료, 사용자 앱 재시도 성공 보고 (2026-09-29)
- 기준: `origin/develop`의 `3b070c9f`
- Flyway migration: 불필요. 기존 V40 기관별 암호문 컬럼을 사용한다.
- 커밋·push·PR: 사용자 요청에 따라 수행. 서버 배포는 범위 밖.

## 커밋 경계

1. `fix(account): CODEF 은행 연결 상태 복구` — 등록 기관 조회, create/add/update 선택, 연결 저장과 보유계좌 조회 분리, 입력 정규화.
2. `fix(account): 저장된 출금계좌 인증정보를 거래내역 조회에 재사용` — 직접 거래내역·정산 조회에서 저장 자격정보 전달.

## 문제와 완료 조건

개발 서버의 기존 connectedId는 로컬에서 연결된 것으로 표시되지만 CODEF `/v1/account/list`에는 등록 계정이 없다. 앱의 `POST /api/v2/accounts/connections/banks`는 로컬 행만 보고 `account/update`를 호출해 502를 반환한다. 또한 CODEF 등록이 성공한 뒤 보유계좌 조회가 실패하면 같은 DB 트랜잭션이 새 connectedId를 롤백한다.

- 기존 연결은 CODEF 등록 기관 목록을 확인한 뒤 create/add/update를 선택한다.
- 등록된 기관이 하나도 없으면 새 connectedId를 만들고 오래된 표시 계좌를 비활성화한다. 과거 정산·거래 행은 삭제하지 않는다.
- CODEF 등록과 로컬 연결 저장을 먼저 확정한 뒤 보유계좌를 조회한다. 조회 실패 시에도 저장된 connectedId와 암호문을 보존한다.
- 한 번 받은 출금계좌 번호·비밀번호를 기관별로 암호화해 저장하고, 연결·보유계좌·직접 거래내역 조회에 재사용한다. 거래내역의 월별 분할 호출은 한 번 복호화한 값을 쓴다.
- 일반 은행에는 추가 필드를 보내지 않고, 평문을 응답·로그·Kafka에 싣지 않는다.
- `birthDate`는 CODEF 요청에서 명시적으로 받은 값만 보낸다. HowMuch 가입일의 생년월일을 은행 본인확인 값으로 추정하지 않는다. 로컬 가상 사용자의 생년월일이 CODEF에 잘못 전송될 수 있다.
- 금융기관 로그인 ID는 테스터처럼 앞뒤 공백을 제거하고, 웹 요청의 기존 필드 검증을 실제 연결 엔드포인트에 적용한다.

## 영향 범위와 결정

- HTTP 요청 형식과 V40 저장 구조는 그대로 사용한다.
- `BankConnectionRegistrationService`가 사용자 잠금과 CODEF 등록·로컬 저장을 한 트랜잭션에 묶는다. `BankAccountService.connect`의 보유계좌 조회는 그 트랜잭션이 끝난 뒤 실행한다.
- CODEF `/v1/account/list`의 `CF-04014` 또는 빈 `accountList`를 등록 계정 없음으로 해석한다. 알 수 없는 응답 구조는 새 연결 생성 전에 실패시킨다.
- 직접 거래내역 조회의 두 호출자(`AccountQueryService`, `SettlementDepositService`)가 저장 자격정보를 전달한다. 출금 비밀번호는 CODEF 전송 직전에 RSA 암호화한다.
- 기존 CODEF 거래내역 명세는 우리은행의 추가 계좌 비밀번호를 필수로 표시하지 않는다. 이번 요청에 따라 해당 필드를 함께 보내되 실제 은행 수용 여부는 로컬 컴파일만으로 검증할 수 없다.

## 검증과 남은 경계

- `./gradlew compileJava --offline`, `git diff --check`를 로컬에서 확인했다. 이번 커밋 요청에서는 테스트를 실행하지 않았다.
- 사용자가 앱 재시도 성공을 보고했다. 이 작업에서 CODEF 성공 응답을 독립적으로 수집하지 않았으므로 기기/은행 동작 증거는 사용자 확인에 한정된다.
- 개발 서버 DB 수정·배포는 수행하지 않는다.
- 금융기관 로그인 방식이 테스터의 성공 방식과 다르면 별도 입력 계약이 필요하다. 현재 앱 연결은 ID/비밀번호(`loginType=1`)다.
- 2026-09-29 로컬 502 로그: `account_create`/우리은행 `CF-12200`. 앱의 CODEF 키와 개발 환경은 테스터와 일치했다. 해당 요청의 실제 은행 인증 값과 CODEF 원문 오류 메시지는 로그에 없어, 생년월일 자동 전송이 유일한 원인인지 실제 재시도로 확인해야 한다.
