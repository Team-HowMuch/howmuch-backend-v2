- 기준일: 2026-10-21 KST
- Flyway migration required: No. 기존 dev 데이터 구조와 전용 JSON 상태를 사용한다.

## 사용자 목표와 계약

부스에서 필요한 그룹 생성/삭제와 여러 정산 시나리오 저장/적용만 남긴다. 정산 행마다 제목·총액·생성자·참여자·며칠 전·정기 여부를 지정한다. 정기 행은 설정과 과거 미납 발생 정산을 함께 만든다. 일반/정기 미납은 같은 그룹의 압축 대상이다.

- 기존 dev ADMIN 인증·Host/Origin 검사·로그인 제한을 유지한다. 사용자 85~88 전용, dev 프로필/DB 제한 유지.
- 그룹 생성은 멤버와 반장을 선택한다. 시나리오는 새 그룹으로 적용하여 기존 체험을 건드리지 않는다.
- 삭제는 시연 사용자만 속한 그룹에 한해 이름 재확인 후 soft delete한다. 과거 정산/입금/압축 기록을 삭제하지 않고 미래 정기 발행만 취소한다. 진행 중인 압축은 차단한다.
- 시나리오는 최대 30개, 정산 20행, 과거 0~60일, 각 2~4명/100~1천만원으로 제한한다. 멤버는 그룹 선택의 부분집합이고 생성자를 포함한다. 균등 분담과 나머지 1원 배분을 사용한다.
- 과거 정산 날짜보다 1분 먼저 그룹/멤버 가입 시각을 구성한다. 다음 정기 발행은 미래 일정으로 계산한다. 기존 사용자의 가입 이전 날짜는 거부한다.
- 그룹/시나리오 적용/삭제 요청은 UUID로 중복 방지한다. 결과 불명 시 같은 UUID를 재전송하며 결정적 invite/정산 ID 및 작업 파일로 복구한다. 변경된 템플릿과 기존 요청을 섞지 않는다.
- 새 경로 `/console/api/booth/{state,templates,apply,groups,delete}`를 기존 관리자 검사 뒤에 연결한다. 과거 기능 경로는 유지하되 새 화면에서 노출하지 않는다.
- 기본 시나리오 3개: 압축 5건, 압축+3일 전 정기 3건, 3/7/14일 전 정기 3건. 사용자가 불러와 수정하고 별도 저장 가능.
- 기존 피그마 기반 화면의 색·타이포·카드 스타일을 재사용한다. 새 제품 API나 Java/스키마 변경은 없다.

## 검증 및 배포

- Python/JS 구문, 저장/잘못된 입력/중복 요청, 실제 새 그룹에 일반·정기 발행/과거 날짜/분담금/압축 대상, 생성한 검증 그룹만 삭제 확인.
- 관리자 로그인·HTTP UI/인증/Origin, 브라우저에서 폼·목록·시나리오 저장/적용 동작 확인.
- 원격 현재 파일을 백업하고 접속 수정 버전은 유지한다. 파일 쓰기 내구성/구문 검증 후 운영 보조 서비스만 재시작한다. 기존 앱/DB 데이터 초기화 없음.
- commit/push/PR 및 새 테스트 파일 없음. 수동 검증 산출물은 임시 비공개 파일로 남긴다.
